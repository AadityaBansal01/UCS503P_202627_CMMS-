# Week 4 --- Diagram Corrections and Backend Preparation

Worked on correcting anomalies and inconsistencies in the system design
diagrams, specifically the UML use-case diagram and the Level 0/Level 1
data-flow diagrams. Reviewed the diagrams against the project
requirements and checked that actors, use cases, processes, data stores,
and data flows represented the same system behavior across the different
diagrams. Corrected mismatched or unclear relationships and flows so
that the final diagrams were internally consistent and could be used as
the basis for implementation.

Also took responsibility for the backend portion of the project, which
will be implemented using MongoDB for data storage. Mapped the backend
responsibility to the system's main data entities, including users,
assignments, meetings, and meeting notes, based on the data stores
already represented in the DFDs. Backend coding has not been started
yet; the current work has focused on making the diagrams accurate and
preparing the database/backend structure that will be implemented in the
next stage. The diagram corrections were important because the final
implementation needs to follow the finalized system design rather than
building the backend around inconsistent or outdated flows.

# Week 5 --- Backend Implementation and API Development

Started the implementation of the backend for the Mentorship Management System based on the finalized system design and data-flow diagrams. Set up the Node.js and Express.js backend structure and configured MongoDB Atlas for persistent data storage using Mongoose. Created the required database models for users, students, faculty/mentors, assignments, meetings, feedback, and meeting notes according to the main entities identified during the system design phase.

Implemented REST APIs for managing users, mentors, students, assignments, meetings, feedback, and notes. Added functionality for user registration and login, mentor allocation, meeting booking, meeting history, mentor availability, assignment management, meeting notes, and department-level summary information. Tested the APIs using Postman and verified that the data was being correctly stored, retrieved, updated, and related through MongoDB.

Implemented authentication using JSON Web Tokens (JWT) and added role-based authorization for students, faculty, and department administrators. This ensures that operations such as mentor requests, mentor approval, and student reassignment can be restricted according to the responsibilities of each user role.

Also implemented and tested the mentor allocation workflow, where a student can submit a mentor request and a faculty member can review and approve the request. The approval process updates the assignment and associates the student with the selected mentor. Additional testing was carried out for administrator functions such as reassigning mentees and viewing department summary statistics.

Integrated the backend APIs with the frontend application and tested the major role-based workflows through the application interface. Verified the student, faculty, and administrator dashboards and checked that actions performed through the frontend were reflected correctly in the backend and database. The main backend functionality is now operational and provides the foundation for further testing, refinement, and deployment of the complete system.

# Weekly Project Progress Journal – College Mentorship Management System (CMMS)

## Week 1 – Project Pitch Deck

Created the initial CMMS project pitch deck in both PPTX and PDF formats, covering the problem statement, motivation, and proposed solution.

- Structured the presentation into four slides: Introduction, Motivation, Problem Statement, and Proposed Solution.
- Identified three major problems in the existing mentorship process:
  1. No centralized scheduling system, resulting in missed or poorly coordinated meetings.
  2. No systematic meeting tracking, making it difficult for departments to monitor meeting frequency and outcomes.
  3. Uneven faculty workload distribution, with limited visibility into the number of students assigned to each mentor.
- Defined four core solution pillars: Automated Allocation, Seamless Scheduling, Progress Dashboards, and Continuous Monitoring.
- Established the initial project scope and design direction, which later formed the foundation of the actual backend modules.
- Designed a minimalist visual theme using a dark-charcoal and off-white palette with a geometric monogram instead of generic stock imagery.

## Week 2 – Project Proposal

Prepared the complete project proposal in LaTeX and PDF formats, following the prescribed course proposal structure.

- Organized the proposal into Introduction and Problem Statement, Objectives, Methodology, Feasibility, Timeline, and Resources and Budget.
- Defined one primary objective and five specific sub-objectives covering mentor allocation, meeting scheduling, dashboards, meeting notes, and administrative visibility.
- Documented the proposed MERN stack architecture, including React frontend, Node.js and Express backend, and MongoDB database.
- Divided the implementation into four major modules: Allocation, Scheduling, Meeting Notes, and Dashboards.
- Defined the development approach using weekly iterations, integration activities, and manual deployment.
- Established testing and validation criteria, including assignment correctness, meeting completion rate, administrative visibility, and user satisfaction.
- Made deliberate scope adjustments to meet the 12-week timeline:
  1. Replaced automated workload balancing with manual administrator reassignment.
  2. Replaced structured progress milestones with a free-text meeting notes feature.
  3. Deferred CI/CD pipelines and automated testing for the current development stage.
- Added Technical, Operational, and Economic Feasibility sections based on the actual project requirements.
- Reviewed and refined the proposal for consistency, clarity, and formal academic presentation.

## Weeks 3 and 4 – System Design, UML Diagrams and DFDs

Worked on the system design phase and prepared the major diagrams required to represent the CMMS architecture and functionality.

**Use-Case Diagram**
- Created a UML use-case diagram containing three actors: Student, Faculty, and Department Admin.
- Identified and modeled 11 major use cases within the CMMS system boundary.
- Included common registration and login functionality for all three actors.
- Used appropriate UML relationships to represent mandatory operations, including booking a meeting slot and checking booking conflicts.
- Cross-checked the use-case diagram with the DFDs to maintain consistency between functional requirements and data flows.

**Data Flow Diagrams**
- Created the Level 0 Context Diagram representing CMMS as a single process interacting with Student, Faculty, and Department Admin.
- Created the Level 1 DFD by decomposing the system into four modules:
  1. Allocation
  2. Scheduling
  3. Meeting Notes
  4. Reporting and Dashboard
- Identified four data stores: Users, Assignments, Meetings, and Notes.
- Maintained Assignments as a separate data store from Users to distinguish mentor-student relationships from user identity information.
- Used standard duplicate-entity notation to maintain diagram clarity and avoid unnecessarily long data-flow connections.
- Verified consistency between the system processes, external entities, and data stores.

## Week 5 – Authentication, Database Seeding and Allocation Engine

Completed the authentication module and implemented the initial mentor allocation functionality.

- Developed the login API using JWT-based authentication and bcrypt password hashing with 10 salt rounds.
- Encoded user roles in JWT tokens to support role-based route protection.
- Implemented ProtectedRoute.jsx to prevent unauthorized users from accessing restricted frontend pages.
- Configured and seeded the database with 25+ mock records consisting of faculty members and student advisees from the CSE department.
- Developed the mentor allocation engine to match students with faculty members based on their department.
- Tested the allocation logic and verified 100% correct department matching in the tested records, with no cross-department assignments.
- Developed the My Mentor page to allow students to view their assigned faculty mentor.
- Completed Milestone M2 (Allocation Engine) within the planned schedule.
